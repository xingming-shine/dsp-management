# 离线驾舱功能核对与实施清单

核对日期：2026-09-09。原型基线：本目录 `data-cockpit.html`，9853 行；不是 `data-cockpit_v1.html`。

## 0. 范围、证据和保护要求

- 本文依据原型 DOM、事件绑定、图表配置、数据生成、计算和导出代码，以及现有 `src/features/data-cockpit` 实现进行静态核对。源码位置为核对时行号。
- 已尝试在浏览器读取现有 HTML 标签页，但被浏览器 URL 安全策略拒绝；因此**不把任何条目标为浏览器点击验证通过**，也不绕过限制。原型浏览器实测仍未完成。
- 初始核对发生于2026-09-09；用户随后确认 mock、数据就绪规则、展示口径和D07组合行为，已进入实施。以下第1–11节保留改造前审计，实施结果见第13节。
- **总览 tab 顶部整个 DSP 排名模块冻结**：奖杯、标题、周期、周/月切换、三个指标、环比、追赶提示及切换、雷达图、布局、间距、渐变透明度和背景效果均保持当前实现；不为了还原新 HTML 修改它的内容。共享组件、日期函数和图表配置的修改也不得间接改变它。
- 独立的“DSP排名”tab 不属于冻结区，需要补全。总览其余运营指标、司机表现属于本次范围。
- 保留当前页面底图、导航外壳与已有用户改动。HTML 的外部字体、独立 CSS、8–11px 图表字、手写按钮和弹层样式不搬进项目。
- “离线”目前按项目中的数据驾舱理解；原型没有业务 API 请求，数据来自静态数组和随机模拟。是否需要真实 API 或完全断网访问，见 D01。

状态约定：**部分实现**＝有界面或入口，但字段、数据关联或行为不完整；**缺失**＝未发现对应实现；**原型待澄清**＝源码存在冲突、占位内容或不可达功能。以下是功能目录，不代表已完成验收。

## 11. 实施前必须确认的规则

### D01 — 交付数据与“离线”的含义

原型是静态/随机模拟数据，无业务接口。建议本次先做**完整前端功能+稳定、可重复的模拟数据**，所有入口、筛选、详情和导出可用，不宣称已接生产数据。“离线驾舱”作为业务名称，不默认扩展为PWA/断网缓存。若需真实数据，请提供接口、权限范围和口径文档。

### D02 — 固定展示数字与明细冲突

例：产能饼图合计1900而妥投卡1820；72H未完结卡14但只有8条运单样例；司机总45但仅10名明细；排名总分133且调整+2，部分分项和、卡片值、详情总分并不一致。

建议：**冻结排名模块不变**；其余使用同一数据源计算卡、图、表、导出，不以互不相符的硬编码数值做验收。如必须保留某组示例数值，请指定它为基准，补足其明细。

### D03 — 更新日与当前日

- 原型写司机“每月5号更新”，但代码`日期<=5`仍回退前两月，即6号才能看上月；排名“每月7号更新”同理8号才看上月。
- 请确认是5/7号当天可用，还是照代码6/8号可用。周排名代码是周三当天可用上周，周一/二仅前两周。
- 日选择器代码允许今天，部分注释和默认fallback使用T-1。建议保留“今天可选+未成熟标更新中”，请确认日数据是否必须只到昨天。

### D04 — 计算口径必须定案

1. 剔除：弹层只减分母，明细表同时扣除被剔除的已妥投量与应派量。建议使用逐票数据：原始分子=原始妥投，原始分母=原始应派；考核分子减被剔除且已妥投的运单，考核分母减去重剔除运单；2400/4800分别维护剔除集合。请确认。
2. 去重：原型原因汇总按周期+指标去重，运单按日期+指标+运单去重；同票跨日重复会导致口径差。建议按选定统计周期+指标+真实运单ID去重，日期保留明细属性；需业务确认跨期重复如何归属。
3. PPH：原型汇总是派送量加权PPH，建议确认是否改为总处理件数/有效工时，以及分母具体包含派件还是全部工作时长。
4. 人均：区间应按去重司机数、司机出勤人次，还是日均人均？原型三处并不统一；司机个人日均已明确按有效派件天数。
5. 质量：原型明细将虚假签收/断更/DNR/客诉等率也用POD抽查量作分母；是否确实如此？请提供这些率的正式分母，不能凭名称猜测。
6. 评分：已知权重/目标与单项满分，但原型没有从指标计算全部得分的正式公式。建议评分作为输入字段展示，先不发明计分曲线。
