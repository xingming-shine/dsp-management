# 实时看板 UI 交互设计文档

> 文档状态：基于当前前端实现整理，并补充评审确认的目标交互  
> 对应路由：`/live-dashboard`  
> 整理日期：2026-09-14  
> 适用端：DSP 管理系统桌面端、平板及移动端自适应页面

## 1. 文档目的

本文档用于统一实时看板的页面结构、信息层级、交互反馈、下钻关系、响应式行为和验收口径。内容以当前仓库实现为基础；标注为“目标行为”或列入“当前实现边界”的内容，是评审后确认但尚未完全落地的交互要求。验收时应先核对实现状态，再按目标行为补齐。

当前页面采用“实时运营总览 + 可展开指标 + 异常处理入口 + 司机/地图联动 + 全页下钻”的看板结构，主要服务于以下场景：

- 快速识别领件分配、站点交取件、派件作业和下期任务的当前进度。
- 从异常指标、图表或 KPI 数值直接定位到司机、任务或运单。
- 在司机列表、运单列表和地图之间交叉核对派件现场状态。
- 在不丢失筛选、分页、滚动位置的情况下连续查看多票运单详情。

## 2. 页面信息架构

```text
应用框架
├── 左侧导航：实时看板入口
├── 顶部栏：面包屑、组织与用户级快捷操作
└── 实时看板主内容
    ├── 工作模式与刷新工具栏
    ├── 业务阶段总览卡片组
    │   └── 单卡展开详情区
    ├── 异常关注指标
    ├── 派送异常原因分布
    └── 司机监控区
        ├── 司机列表/领件监控
        └── 派件地图监控

全页下钻
├── 任务分配
├── 领件详情
├── 应退回
├── 派件指标详情
├── 异常指标详情
├── 派送异常分布详情
└── 司机监控：运单视图 / 地图视图

单票上下文
├── 运单工作台：筛选结果内连续浏览
├── 运单详情：收件信息 / POD 信息 / 问题件记录 / 操作记录
└── POD 详情：签收信息 / 审核记录 / 图片预览
```

### 2.1 核心指标口径

| 指标 | 计算或构成 | 展示规则 |
| --- | --- | --- |
| 分配完成率 | 已分配件量 ÷ 应领件 × 100% | 分母为 0 时显示 `0.00%`，不显示 `NaN` 或无穷值 |
| 领件率 | 当前周期任务已领件 ÷ 当前周期应领件 × 100% | 当期与下期使用各自周期数据；非当前周期领件不进入分子 |
| 领件总量 | 当前周期任务领件 + 非当前周期任务领件 | 与构成图、司机表和运单筛选保持同一口径 |
| 应派件 | 当期应派 + 历史未派；同时等于已签收 + 派送异常 + 非标退回 + 待派件 | 四个状态占比之和按两位小数校准为 100% |
| 2400 妥投率 | 当期应派中已签收 ÷ 当期应派 × 100% | 只使用当期应派，不混入历史未派 |
| 日清率 |（已签收 + 派送异常）÷ 应派件 × 100% | 非标退回不计入日清完成量 |
| 妥投率 | 当前完整司机监控按已签收 ÷ 应派件展示；派件明细司机表当前按已签收 ÷（已签收 + 派送异常）展示 | 当前存在分母不一致，目标行为需由产品确认后统一，统一前必须在 Tooltip 中展示分子和分母 |

## 3. 全局框架与布局

### 3.1 应用框架

- 左侧导航桌面端默认以图标态显示，悬停可覆盖展开；当前“实时看板”项使用 2px 品牌橙短指示条标识。
- 移动端不常驻侧边栏，通过顶部栏菜单按钮打开侧边 Sheet。
- 顶部栏固定在视口顶部，高 56px；页面滚动超过 10px 后，底部分隔线转为轻阴影。
- 顶部栏左侧为面包屑，右侧为组织、下载中心、关联系统和用户操作。窄屏会折叠中间层级面包屑。
- 主内容区域使用 16px 页面内边距，全宽承载密集运营信息，不设置额外最大宽度。
- 页面画布使用冷浅灰背景，Card、表格和详情面使用白色内容面；主体模块之间默认使用 12px 间距。

### 3.2 顶部业务工具栏

工具栏位于看板总览最上方，左右分布：

- 左侧为工作模式切换按钮。
  - 当日派：显示“上午领件 → 下午派件”。
  - 隔日派：显示“下午领件 → 次日派件”。
  - 点击后立即切换模式，并通过 `workMode=same-day|next-day` 写入当前 URL。
  - 工作模式改变后，顶部业务阶段卡片的顺序、标题和下期任务数据同步变化。
- 右侧显示数据更新时间与刷新图标。
  - 当前实现按默认纽约时区显示完整日期时间，并精确到秒。
  - 点击刷新后更新页面中的刷新时间，并显示“刷新成功” toast。
  - 60 秒内重复手动刷新会被拦截，并提示“操作太频繁，休息一下”。
  - 当前实现仅更新前端刷新时间，尚未触发真实数据重新请求。

## 4. 总览区域

### 4.1 业务阶段卡片组

卡片组位于一个统一 Card 内容面内。隔日派在宽度达到 1024px 时可按比例同排展示四个业务阶段；当日派需要达到 1280px 才完整同排。更窄视口改为多行网格，不压缩基础字号。

| 工作模式 | 卡片顺序 | 主要信息 |
| --- | --- | --- |
| 当日派 | 当期领件任务分配 → 站点交取件 → 派件作业 → 下期领件任务 | 未分配件量、领/退件、派件结果、下期推送时间或任务进度 |
| 隔日派 | 当期领件任务 → 派件作业 → 下期领件任务分配 → 站点交取件（下期领件任务） | 当期领件、当前派件、下期分配、下期交取件 |

卡片通用规格与交互：

- 卡片默认高度约 192px，使用序号、标题、核心数值、辅助进度和右侧展开箭头建立层级。
- 整卡可点击和键盘聚焦；`Enter` 或 `Space` 与鼠标点击行为一致。
- 同一时间只允许展开一张卡片。再次点击已展开卡片或按 `Escape` 可收起。
- 选中卡片使用品牌选中面、橙色边框和向下指针，与紧邻其下的展开详情区形成视觉连接。
- 展开详情以 260ms 淡入并上移 8px；系统启用“减少动态效果”时取消动画。
- 卡片内可下钻的数值是独立按钮。点击数值只进入对应明细，不触发整卡展开/收起。

### 4.2 各卡片内容

#### 当期领件任务分配

- 主指标为“未分配件量”，使用异常语义强调。
- 底部显示任务分配完成率进度条与百分比。
- 点击未分配件量进入“未分配件量明细”。
- 展开后显示任务总量、已分配、未分配和完成率关系；各段数值可继续下钻到任务分配列表。

#### 站点交取件

- 左侧显示领件总量与未领件，底部显示领件率。
- 右侧显示待退回数量。
- 点击领件相关数字进入“领件详情”；点击待退回进入“应退回”。
- 展开后由三部分组成：
  - 站点领件：瀑布/构成图 + 领件总量、未领件的父子指标。
  - 退回站点：两组“应退回 − 已退回 = 待退回”关系。
  - 指标说明：站点领件/退回站点定义，可通过页签切换并在区域内滚动。

#### 派件作业

- 是总览中唯一持续加强的业务卡片，使用浅品牌选中底纹和品牌序号强调。
- 展示应派件、当期应派、待派件、日清率和 2400 妥投率。
- 日清率和 2400 妥投率使用环形图；点击或键盘操作可展开结构化 Tooltip 查看计算明细。
- 点击应派件或待派件进入对应司机/运单明细。
- 展开后提供：
  - “全部应派件 / 当期应派 / 历史未派”范围切换。
  - 已签收、派送异常、非标退回、待派件的分段进度和数值。
  - 分段本身及对应指标均可点击下钻。
  - 指标定义区在桌面端位于右侧，窄屏堆叠在主指标区之后。

#### 下期领件任务

- 数据尚未推送时显示预计推送日期和精确到秒的时间。
- 有数据时显示未分配件量与分配完成率。
- 展开后，无数据使用标准 Empty 状态；有数据则复用任务分配详情结构。

### 4.3 隔日派 KPI 下钻映射

切换到隔日派后，四张业务阶段卡片依次为“当期领件任务 → 派件作业 → 下期领件任务分配 → 站点交取件（下期领件任务）”。KPI 点击必须同时传递业务周期、指标类型和指标对应的默认筛选，不能只打开一个未区分来源的通用详情页。

| KPI 卡片 | 点击入口 | 目标界面 | 初始视图与默认筛选 |
| --- | --- | --- | --- |
| 当期领件任务 | 领件总量 | 领件详情 | `taskPeriod=current`；默认司机视图，展示全部当期司机及领件构成 |
| 当期领件任务 | 未领件 | 领件详情 | `taskPeriod=current`；默认司机视图，突出未分拣未领件、已分拣未领件及未领件合计 |
| 当期领件任务 | 领件率 | 当前卡片只读进度 | 不下钻；通过可访问名称说明计算分子、分母和比例 |
| 当期领件任务展开区 | 应领件、领件总量 | 领件详情 | 保留当期周期；进入全部司机范围，不预设单个司机 |
| 当期领件任务展开区 | 未分拣未领件、已分拣未领件 | 领件详情 | 切入运单视图，并分别预选对应领件状态；点击未领件合计时同时预选两种未领件状态 |
| 当期领件任务展开区 | 当期任务领件、非当期任务领件 | 领件详情 | 切入运单视图；领件状态为已领件，并分别预选“今日派件任务=是/否” |
| 派件作业 | 应派件 | 应派件详情 | 默认司机视图、全部应派件范围；提供全部应派件/当期应派/历史未派页签 |
| 派件作业 | 待派件 | 待派件详情 | 默认司机视图、全部来源；展示待派件、未超期、超 1–4 天、最新操作及时间 |
| 派件作业 | 当期应派提示数值 | 当前卡片只读来源提示 | 不单独下钻；展开卡片后可通过“当期应派”来源数值进入对应详情 |
| 派件作业 | 日清率、2400 妥投率 | 结构化 Tooltip | 比例指标只解释口径和组成，不进入独立详情；触发器支持点击、触屏和键盘访问 |
| 派件作业展开区 | 已签收、派送异常、非标退回、待派件 | 对应派件指标详情 | 继承当前选中的全部/当期/历史范围，并将指标对应状态作为默认筛选 |
| 派件作业展开区 | 全部应派件、当期应派、历史未派数值 | 应派件详情 | 默认司机视图，并直接选中对应派件来源页签 |
| 下期领件任务分配 | 未分配件量 | 任务分配详情 | `taskPeriod=next`；任务范围为下期领件任务，默认“是否分配快递员=未分配” |
| 下期领件任务分配 | 分配完成率 | 当前卡片只读进度 | 不下钻；通过可访问名称说明完成率 |
| 下期领件任务分配展开区 | 应领件 | 任务分配详情 | `taskPeriod=next`；显示下期任务标题和全部分配状态；任务数仅作为辅助统计展示 |
| 下期领件任务分配展开区 | 已分配、未分配及进度分段 | 任务分配详情 | `taskPeriod=next`；分别预选已分配或未分配状态 |
| 站点交取件（下期领件任务） | 领件总量 | 领件详情（下期领件任务） | `taskPeriod=next`；默认司机视图，展示下期任务领件和非下期任务领件构成 |
| 站点交取件（下期领件任务） | 未领件 | 领件详情（下期领件任务） | `taskPeriod=next`；默认司机视图，突出下期未领件指标 |
| 站点交取件（下期领件任务） | 领件率 | 当前卡片只读进度 | 不下钻；通过可访问名称说明下期任务领件、应领件和比例 |
| 站点交取件展开区 | 未分拣未领件、已分拣未领件、下期/非下期任务领件 | 领件详情（下期领件任务） | 切入运单视图，并带入对应领件状态和任务归属筛选 |
| 站点交取件（下期领件任务） | 待退回 | 应退回详情（下期领件任务） | `taskPeriod=next`；默认司机视图；当前无数据时保留周期上下文并显示标准 Empty |
| 站点交取件展开区 | 两类退回的应退回、已退回、待退回 | 应退回详情（下期领件任务） | 带入派送异常或错分/No Scan 退回类型，并根据入口预选全部、已退回或待退回状态 |

隔日派下钻通用规则：

- 详情页标题与面包屑必须明确显示“当期”或“下期领件任务”，避免同名页面丢失周期语境。
- 从具体 KPI 进入时，入口筛选视为“下钻初始条件”；点击重置恢复该入口的初始条件，而不是无条件清空为全部数据。
- 领件和退回详情使用“司机视图 / 运单视图”线型页签。点击司机指标后切换到运单视图，并继续携带司机、状态、任务归属或退回类型。
- 派件指标详情使用“司机视图 / 运单视图”；应派件详情额外提供来源页签，来源切换后统计、表格、排序、分页和导出使用同一结果集。
- 点击任务编号或运单编号可继续进入任务运单列表或单票运单工作台；返回时恢复 KPI 来源、业务周期、筛选、页签、分页及滚动位置。
- 若下期数据尚未推送，详情仍展示正确标题、面包屑和必要筛选上下文，并以 Empty 说明暂无数据；不得回退到当期数据或显示无周期的通用页面。
- 非下钻型比例指标不使用与可下钻数值相同的链接视觉。其 Tooltip 关闭后焦点返回比例指标触发器。

### 4.4 异常关注与固定快捷导航

异常关注区按业务分为两组：

- 妥投异常：POD 不合规、妥投位置异常。
- 问题件：待处理、其中疑似丢失、进行中、虚假签收、DSP 轨迹断更。

交互规则：

- 每个指标块显示数量和名称；鼠标悬停或键盘聚焦展示口径说明。
- 点击指标进入对应异常详情；“疑似丢失”作为“待处理”的子指标，以连接气泡样式表达从属关系。
- 紧急项使用异常色，普通信息项保持中性，不以品牌橙代替业务状态。
- 当页面滚动使原异常区越过顶部后，异常指标会固定在顶部栏下方形成快捷导航。
- 固定导航支持手动收起；收起后保留“展开异常指标”按钮。回到原区域后固定导航自动消失并恢复默认展开状态。

### 4.5 派送异常原因分布

- 使用横向堆叠条形图表达各异常原因中的正常问题件和虚假问题件。
- 图例、坐标轴和 Tooltip 使用项目统一图表样式，图表颜色与业务语义保持一致。
- 标题可聚焦查看指标口径说明。
- 右上角“详情”进入派送异常分布详情页。

### 4.6 司机监控与地图联动

桌面端使用约 11:9 的双栏布局：左侧司机监控，右侧派件地图；整区最小高度约 880px，地图内容最小高度约 640px。

司机监控含三个主页签：

- 当期领件任务监控。
- 派件监控，默认选中。
- 下期领件任务监控。

派件监控交互：

- 顶部提供异常快捷数量、PPH、司机姓名查询、异常状态多选和排序。
- 司机卡片显示路区、派件结果、日清进度、异常标签、最新状态和联系方式。
- 点击卡片选中司机，并同步高亮右侧地图标记；再次点击已选司机可取消选择。
- 点击 POD 或异常标签进入该司机的运单视图，并带入对应异常筛选。
- 司机列表选中项变化时，会自动滚动到可见区域。

地图交互：

- 显示司机实时位置，选中状态与司机列表双向同步。
- 支持点击标记、键盘聚焦、缩放、拖拽和平移。
- 提供缩小、放大、恢复初始视野控件；缩放范围为 1–2 倍，步长 0.25。
- 右上角“详情”进入完整司机监控地图。

## 5. 全页下钻与导航

### 5.1 通用规则

- 下钻后总览区域保留挂载但视觉隐藏，避免返回时重建整页状态。
- 页面顶部面包屑同步更新为“实时看板 / 当前详情”；可通过面包屑返回看板。
- 详情页左上角提供“返回”按钮，标题使用 20px/600。
- 进入详情前记录看板滚动位置；返回看板后恢复原滚动位置。
- 详情使用淡入 + 从右侧轻移入动画；减少动态效果模式下取消动画。
- URL 只同步部分全页状态；写入方式和浏览器历史行为如下：

| 状态 | URL 参数 | 写入方式 | 浏览器前进/后退恢复范围 |
| --- | --- | --- | --- |
| 工作模式 | `workMode` | 模式切换使用 `replaceState` | 刷新或读取 URL 时恢复；切换本身不创建独立历史节点 |
| 司机监控首次进入 | `view=driver-map`、`driverId`、`alertType`、`deliveryStatus`、`monitorView` | 进入详情使用 `pushState` | 可恢复司机、异常、派件状态和初始视图 |
| 司机监控内筛选 | `driverId`、`alertType`、`deliveryStatus` | 修改后使用 `replaceState` | 当前历史节点可恢复；不会为每次筛选建立历史节点 |
| 领件详情 | `view=pickup`、`driverId`、`taskPeriod` | 进入详情使用 `pushState` | 可恢复周期及可选司机 |
| 应退回 | `view=return`、`taskPeriod` | 进入详情使用 `pushState` | 可恢复周期 |
| 异常指标 | `alertMetric` | 进入详情使用 `pushState` | 可恢复异常指标类型 |
| 任务分配、派件指标、异常分布和单票工作台 | 当前无完整 URL 参数 | 仅保存在组件状态 | 刷新或直接分享 URL 不能恢复完整上下文 |

- `popstate` 当前只重建司机监控、领件、应退回和异常指标等已登记状态；任务分配、派件指标和单票工作台不应宣称支持深链接。
- 司机监控的 `monitorView` 用于初始进入；页面内切换运单/地图视图当前不会持续更新该参数。
- 从异常原因分布继续进入派送异常运单时，父级返回关系保存在内存中；返回按钮恢复父级分布页面，但刷新后不保留这层关系。
- 从详情返回总览时清理详情参数并恢复进入前的看板滚动位置；工作模式参数继续保留。

### 5.2 任务分配

- 查询条件：任务编号、领件状态多选、是否分配快递员。
- 表格字段：任务编号、推送时间、派件日期、路区、分配/取件快递员、快递员路线、领件状态、运单数量、未领件量和操作。
- “未领件量”支持升序/降序切换。
- 点击任务编号进入该任务的运单列表；点击未领件量会自动带入两种未领件状态。
- 已分配任务提供“联系司机”，打开紧凑 Dialog，并默认聚焦“复制手机号”。

### 5.3 领件详情

使用“司机视图 / 运单视图”线型页签。

司机视图：

- 查询条件为司机、签到状态、签退状态。
- 表格展示应领件、未分拣未领件、已分拣未领件、当期/非当期任务领件、领件总量等连续指标。
- 指标列可排序；点击司机指标直接切到运单视图并带入司机和领件状态。
- 操作列固定在表格最右侧，提供联系司机。

运单视图：

- 查询条件为司机、完整运单编号、领件状态多选、是否今日/下期派件任务。
- 支持按业务字段排序、导出当前已提交筛选结果和分页。
- 点击运单编号进入单票运单工作台。

### 5.4 应退回

同样使用“司机视图 / 运单视图”结构。

- 司机视图查询司机、签到状态和签退状态，连续展示两类退回的应退回、待退回及合计。
- 点击任一数量切到运单视图，并自动带入司机、退回原因和状态。
- 运单视图支持司机、完整运单编号、退回状态和退回原因多选筛选，并支持导出。
- “下期领件任务”的应退回详情当前展示空数据状态。

### 5.5 派件指标详情

由总览中的应派件、待派件、已签收、派送异常或非标退回进入。

- 顶层页签为“司机视图 / 运单视图”。
- 应派件场景额外提供“全部应派件 / 当期应派 / 历史未派”范围页签。
- 司机视图通过可点击数值继续下钻到该司机的运单列表。
- 运单视图根据指标动态组合筛选项，包括司机、运单编号、派件状态、派件来源、超期天数、运单类型、今日转派、妥投异常、问题件类型和是否虚假问题件。
- 表头排序采用上下箭头；再次点击同一字段切换方向，切换字段时默认升序。
- 宽表格只允许表格区域自身横向滚动，不产生页面级横向滚动。

### 5.6 异常指标详情

- 右侧提供异常指标快速切换栏；在普通详情中可收起，选中项使用品牌选中态。
- POD 不合规和妥投位置异常使用运单卡片列表，支持按司机和运单号筛选。
- 待处理、进行中、疑似丢失、虚假签收和 DSP 轨迹断更使用问题件任务表格。
- 问题件筛选随指标变化，可能包含司机、完整运单号、断更时长、处理指令、问题件类型和是否虚假问题件。
- 待处理/疑似丢失记录显示“处理问题件”，当前点击仅显示“暂未接入”的信息 toast。

### 5.7 派送异常分布详情

- 首屏并列展示“异常原因分布”和“异常量人员分布”。
- 下方按异常原因展示司机分布图矩阵。
- 司机较多时图表自身横向滚动，保持图表最小可读宽度。
- 点击任一图表柱段，进入派送异常运单视图，并自动带入司机、异常原因和是否虚假问题件。

### 5.8 完整司机监控

页面顶部包括返回、标题、运单/地图视图切换；地图视图额外显示司机选择器和异常状态。

固定的指标汇总条包括：

- 应派件与当期应派。
- 已签收、派送异常、非标退回、待派件。
- POD 不合规、妥投位置异常、虚假问题件快捷筛选。
- 2400 妥投率、妥投率和日清率。

视图行为：

- 从普通“司机监控地图”入口进入时默认地图视图；从司机的 POD、妥投位置异常或虚假问题件入口进入时默认运单视图，并带入对应异常筛选。
- 点击汇总指标会立即更新运单筛选。
- 运单视图桌面端为“司机列表 448px + 运单列表自适应”双栏。
- 地图视图保留运单筛选，并用地图替代司机列表；用户可控制是否显示运单标记。
- 运单视图与地图视图分别记录内部滚动位置和选中运单；往返切换后恢复各自状态。地图采用延迟挂载，仅在首次进入地图视图时初始化。
- 运单查询支持运单号、邮编或地址关键词三种字段，以及派件状态、异常状态和排序。
- 查询使用“草稿条件—已提交条件”模式；点击查询才应用，重置恢复默认。
- 地址默认脱敏。点击眼睛图标按单票加载完整地址；加载中只禁用该运单的地址按钮，再次点击可隐藏完整地址。
- 地址关键词查询和单票地址解密分别显示忙碌状态。切换司机、重新查询或离开页面时中止旧请求，避免过期结果覆盖当前视图；失败显示错误 toast，其他运单数据保持不变。
- 运单列表分批加载，滚动接近底部时继续追加，不使用页码分页。

地图图层与联动：

- 地图提供“司机最新位置”和“显示运单”两个图层开关。司机图层可独立关闭；运单图层仅在选择单个司机后允许开启。
- 在“全部司机”范围尝试开启运单图层时保持关闭，并通过信息 toast 提示先选择单个司机。
- 点击司机标记打开司机摘要并将视野平滑移动至该司机；再次点击已选司机可取消弹出信息。
- 点击运单标记后选中对应运单，自动扩充已加载批次、滚动到卡片并转移键盘焦点；重复点击同一标记仍执行定位。
- 点击运单卡片会反向驱动地图定位，并将视野移动到对应坐标和约 16 级缩放。缺少有效坐标时保留卡片选中并显示信息 toast。
- 筛选结果变化只更新标记，不自动重置用户已经调整的地图视野；只有显式选择卡片、标记或点击“地图复位”时改变视野。
- 地图提供放大、缩小和按当前可见标记复位控件，并显示派件状态图例。地图未初始化时控件禁用。
- 底图初始化或瓦片加载期间显示局部 Skeleton；失败时在地图内显示 Alert 和“重试”，不阻塞页面其他区域。
- 已签收或派送异常且具有有效采集坐标的运单提供外部地图跳转；待派件、非标退回或无效坐标不显示该入口。

## 6. 单票运单工作台

从表格运单号、异常卡片、POD 图片或司机监控运单卡片进入。工作台替换原列表内容，但保持原列表组件挂载，以保留筛选、排序、分页和横向滚动状态。

### 6.1 桌面结构

- 顶部：返回列表、当前工作台标题、“第 N / 总数 件”、上一件、下一件。
- 主体：304px 运单卡片轨道 + 自适应详情面板，间距 16px。
- 运单卡片标准高 112px、间距 8px；大数据量场景使用虚拟化，只渲染可视区附近卡片。
- 详情区域内嵌运单详情或 POD 详情，不再叠加第二层抽屉边框。
- 工作台高度为 `100dvh - 88px`，最小高度 448px，内部区域独立滚动。

### 6.2 导航与状态恢复

- 点击左侧卡片更新详情；上下方向键切换相邻运单。
- 顶部上一件/下一件按钮与卡片选择保持同步，首尾按钮禁用。连续浏览范围是当前完整筛选结果，不限于进入工作台时所在的当前分页。
- `Escape` 返回列表；若焦点位于 Dialog、菜单或 Tooltip 内，不触发工作台关闭。
- 浏览跨越分页边界后关闭工作台时，根据当前锚点自动切换到其所属页，再恢复进入前的页面滚动位置和目标行焦点，并短暂使用品牌选中底色标记返回行。
- 若当前选中卡片已滚出轨道，返回时以第一张可见卡片作为锚点，避免列表跳回旧位置。
- 支持 View Transition 的浏览器使用列表到详情的空间连续动画；减少动态效果模式下直接切换。

### 6.3 移动端

- 工作台一次只展示“运单列表”或“详情”其中一个区域。
- 顶部“切换运单 / 查看详情”按钮在两者之间切换。
- 选择一张运单后自动进入详情，不把双栏强行缩窄到移动端。

### 6.4 运单详情结构

- 独立打开时使用右侧 Sheet：移动端占满可用宽度，桌面端约为视口宽度的 85%；嵌入工作台时去除外层 Sheet 边框和遮罩，直接使用详情内容面。
- 顶部显示运单编号、复制按钮和运单状态。复制成功或失败使用 toast；图标按钮提供明确的可访问名称。
- 主体左侧首先展示国家、州/省、郡县、邮编、区域和收件地址等收件人信息。
- 附加信息使用“POD 信息 / 问题件记录”页签。POD 表格展示签到类型、POD 图片、签收快递员、签收日期和妥投时效；问题件表格展示异常、图片、处理指令及处理/上报记录。
- POD 缩略入口打开大图 Dialog；Dialog 提供隐藏标题和说明，关闭后返回原图片入口。
- 主体右侧为操作记录时间轴，展示动作、发生时间、操作人和地点；窄屏时移动到主信息下方并使用独立纵向滚动。
- 空问题件记录使用表格内 Empty，不移除页签和表头上下文。

### 6.5 POD 详情与图片浏览

- 顶部显示运单编号、复制运单号和关闭按钮；打开后焦点进入关闭按钮，关闭后返回原触发器。
- 桌面端左侧为签收信息与 POD 审核记录，右侧为大图预览；嵌入工作台时使用工作台详情面尺寸，独立打开时使用右侧 Sheet。
- 签收信息包括签收人、签收类型、签收时间和收件地址。完整地址按需读取，不因查看 POD 自动暴露。
- 最新提交和历史审核记录分别展示缩略图组；选择不同提交批次或缩略图后，大图、序号和审核上下文同步更新，并将预览区域滚动到可见位置。
- 图片画布支持左右方向键切换；底部同时提供上一张、下一张按钮和“当前序号 / 总数”的 `aria-live` 状态。首尾按钮禁用。
- 图片加载中显示局部 Skeleton；无图片显示 Empty；加载失败显示错误 Empty 和“重新加载”，切换或重试不关闭详情。
- 审核记录按时间展示核查机构、合规状态、不合规原因和对应提交图片；无审核记录时显示明确的只读空状态。

## 7. 筛选、排序、分页与导出规则

### 7.1 筛选

- 常规数据列表使用统一 QueryFilterLayout。
- 桌面端每行最多四个等宽字段；少于四个字段时，查询和重置占用最右列。
- 四个及以上字段时，操作独立成行：导出在左，查询与重置在右。
- 窄屏按单列/双列逐步堆叠，操作允许换行，不隐藏高频条件。
- 下拉多选在控件内显示选中项，不在工具栏下方重复展示筛选标签。

当前各区域的筛选触发方式并不完全相同：

| 区域 | 条件应用方式 | 快捷指标 | 重置行为 |
| --- | --- | --- | --- |
| 总览派件司机列表 | 司机姓名和异常多选输入即生效 | 无独立提交步骤 | 清空姓名、异常及排序 |
| 当前/下期领件监控 | 表单草稿点击“查询”后生效 | 未签到、未签退等汇总指标立即应用 | 恢复全部状态、默认排序和第 1 页/顶部 |
| 完整司机监控运单查询 | 草稿点击“查询”后生效；地址查询为异步请求 | 汇总状态和异常指标立即更新已提交条件 | 清空查询、状态、地址结果和排序，并滚动到顶部 |
| 任务分配、领件、退回和派件详情 | 查询工具栏草稿点击“查询”后生效 | 司机表内指标立即切换到运单视图并带入筛选 | 当前主要恢复全部条件和第 1 页；部分页面尚未同步清除排序 |
| 从总览 KPI 进入详情 | 入口参数直接作为初始已提交条件 | KPI 本身即快捷入口 | 目标行为是恢复该 KPI 的初始条件，而不是无条件回到全部数据 |

- 输入即生效的区域不得显示一个不实际控制结果的“查询”按钮；提交式区域必须区分草稿条件和已提交条件。
- 点击查询后回到第 1 页或列表顶部，并清除与旧结果绑定的选中项。
- 目标重置行为是清除用户新增条件、排序和局部展开状态，同时保留由上级 KPI 定义的业务周期与入口范围；当前未统一的页面列入第 12 章实现边界。

### 7.2 排序

- 独立排序入口使用“上下箭头 + 当前排序名称”下拉菜单。
- 非默认排序时仅图标变为品牌橙，文字保持中性。
- 表头排序使用紧贴字段名的升/降序双箭头，并通过 `aria-label` 声明当前方向。
- 排序对已提交的筛选结果生效，并将页码或列表位置复位到顶部。
- 排序选择后立即生效，不提交尚未查询的草稿条件；重置是否同时恢复默认排序必须由当前页面规则明确说明。

### 7.3 分页与导出

- 完整分页能力包括总记录数、10/20/50 每页、上一页、页码、下一页和跳页。当前实时看板的大多数任务、领件、退回和派件详情显式关闭跳页，问题件等列表按组件默认配置显示；验收应按页面配置核对，不能假定所有页面都有跳页。
- 切换每页条数后回到第 1 页。
- 目标布局是表格与分页共享同一数据区域和 1px 外框，分页只使用顶部内分隔线；当前仍有页面将分页作为表格后的相邻节点，视觉上不得形成第二层 Card。
- 进入单票工作台后，上一件/下一件基于完整已提交筛选结果连续浏览，不受当前分页限制；退出时自动返回锚点所属页。
- 导出基于当前已提交筛选结果生成 CSV，并通过 toast 反馈成功。

## 8. 视觉与组件规范

| 项目 | 设计规则 |
| --- | --- |
| 画布 | 冷浅灰 `#f5f6f9`；Card、表格和弹层为白色 |
| 品牌强调 | GOFO 橙仅用于主按钮、选中、悬停、焦点和少量品牌识别 |
| 数据主色 | 青绿为领先分析色；蓝、青、琥珀、紫、珊瑚按固定顺序扩展 |
| 状态色 | 成功、提醒、异常分别使用 success、warning、destructive，不用品牌橙冒充 |
| 字体 | 苹方优先；正文 14px/400，表格与辅助文字 12px，详情标题 20px/600 |
| 数字 | 数量、百分比、日期时间统一使用等宽数字 `tabular-nums` |
| 日期时间 | `MM/DD/YYYY`、`MM/DD/YYYY HH:mm`、`HH:mm:ss`，24 小时制 |
| 圆角 | 基础 6px；控件约 4.8px，Card/Dialog 约 8.4px |
| 边框 | 结构线统一 1px；同一表面不同时使用静态边框和阴影 |
| 主按钮 | 36px 高、13px/400、品牌橙实底；每个操作区只保留一个主按钮 |
| Tabs | 主模块使用 44px 高线型 Tabs，选中态为 2px 品牌橙指示线 |
| 表格 | 12px 文字、48px 表头/行高、浅色表头、横向分隔线，无默认斑马纹 |
| 浮层 | Tooltip 承载短说明；Dialog 承载联系信息；长详情使用 Sheet 或工作台 |
| 深色模式 | 使用 `globals.css` 中同名语义 token 保持系列色和状态身份；业务组件不单独硬编码深色覆盖 |

- 实时看板不单独提供主题切换入口，跟随应用级主题状态。浅色与深色模式下应保持同一指标的图表颜色、状态语义和选中关系。
- 地图底图在样式加载后读取地图语义 token 调整陆地、水面、道路和建筑颜色；主题变化不得影响标记与状态图例的辨识度。

## 9. 反馈状态与异常处理

| 场景 | 反馈方式 |
| --- | --- |
| 刷新成功 | 成功 toast + 更新时间变化 |
| 高频刷新 | 信息 toast，保留当前页面状态 |
| 查询/重置 | 数据刷新、回到第 1 页，部分页面附成功 toast |
| 导出成功 | 成功 toast + 浏览器下载 CSV |
| 复制手机号成功/失败 | 成功或错误 toast；失败时保留号码供手动复制 |
| 地址加载中 | 局部 Skeleton 或 busy 状态 |
| 地址加载失败 | 错误 toast/重试入口，不清空其他运单数据 |
| 无筛选结果 | Empty + 原因说明 + 重置入口 |
| POD 无图片/加载失败 | Empty + 说明；失败时提供重新加载 |
| 地图/图片加载 | 只阻塞对应局部区域，不锁定整页 |
| 尚未接入操作 | 信息 toast 明确说明当前不可完成 |

联系方式交互按信息密度分为两种：

- 总览司机卡片和领件监控使用轻量联系浮层。鼠标移入、键盘聚焦或点击司机名称均可打开；指针从触发器移动到浮层时保持打开，短延迟离开后关闭。
- 全页任务、领件、退回和派件详情使用紧凑 Dialog，展示司机名称、手机号和“复制手机号”；打开后默认聚焦复制按钮，关闭后焦点返回原操作入口。
- 复制成功显示成功 toast；剪贴板不可用时显示错误 toast，同时保留可选择的手机号供手动复制。

## 10. 无障碍与键盘交互

- 所有图标按钮必须有中文可访问名称，非直观图标通过 Tooltip 补充说明。
- 卡片、指标、图表说明、地图控件、页签、筛选、排序和分页均支持键盘操作。
- 键盘焦点使用 1px 品牌橙焦点环，不仅依赖颜色表达当前状态。
- 展开卡片使用 `aria-expanded` 和 `aria-controls` 关联详情区。
- 选中司机、指标和运单使用 `aria-pressed` 或 `aria-current` 表达持续状态。
- 图表提供可访问名称和文字化指标，关键信息不只存在于 Tooltip 中。
- Dialog/Sheet 提供标题与说明；关闭后焦点返回原触发器或对应列表行。
- 复杂列表支持上下方向键；`Escape` 按当前层级关闭工作台或详情。
- 遵循 `prefers-reduced-motion`，在用户减少动态效果时移除非必要动画。

## 11. 响应式行为

### 宽桌面（≥ 1280px）

- 侧边栏以图标态常驻并支持覆盖展开。
- 当日派使用 24 栅格完成四阶段同排；隔日派使用四段业务比例同排。
- 司机监控与地图并排；展开详情中的主指标和指标说明也可并排。
- 完整司机监控使用司机列表 + 运单列表或地图双栏；运单工作台使用 304px 卡片轨道 + 自适应详情双栏。
- 宽表格在自身视口内横向滚动，最右操作列保持固定。

### 窄桌面（1024–1279px）

- 隔日派四张卡片可按 `5fr / 8fr / 3fr / 8fr` 比例同排；当日派仍按 12 栅格分成两行，不宣称四卡同排。
- 司机监控与地图根据容器宽度并排或上下排列；不得通过缩小字体强行维持双栏。
- 展开详情的三栏结构逐步收为两栏或单栏，指标说明移动到主内容之后。
- 查询字段最多四列；字段或操作不足时允许自然换行。

### 平板（768–1023px）

- 当日派和隔日派卡片均允许形成两行或三列网格，保持原业务顺序。
- 司机监控与地图改为上下排列；地图保留最小可操作高度。
- 查询字段优先两列，宽表格仅在自身区域横向滚动。
- 运单详情和 POD 详情由并排信息区逐步改为上下分区。

### 移动端（< 768px，参考 390 × 844）

- 侧边导航改为 Sheet；顶部面包屑折叠中间层级。
- 页面保持 16px 画布边距，不允许整体横向滚动。
- 总览卡片单列排列，核心指标优先于说明内容。
- 完整司机监控提供“司机列表 / 运单列表 / 地图”区域切换，一次只展示一个主区域。
- 运单工作台使用列表/详情单面板切换。
- 表格允许自身横向滚动，不缩小到 12px 以下；移动端表单控件文字至少 16px。
- 分页精简为关键页码和图标式上一页/下一页，避免超出视口。

## 12. 当前实现边界

- 页面数据目前主要来自本地 mock 数据，不代表真实接口刷新频率和网络延迟。
- 手动刷新尚未调用数据接口，仅更新刷新时间与 toast。
- 顶部时区切换尚未传入实时看板 formatter；看板时间当前固定使用默认纽约时区。
- “处理问题件”尚未接入真实处理抽屉或提交流程。
- 地址查询具备异步加载与失败反馈，但依赖当前演示 API。
- 下期交取件和应退回在部分模式下使用空数据演示。
- 当期/下期领件卡片中的细分 KPI 当前主要打开通用领件详情，尚未全部按入口预设未领件类型、已领件状态和任务归属；文档中的映射为应补齐的目标行为。
- 下期领件任务分配入口已携带 `taskPeriod=next`，但当前任务分配详情尚未消费该周期参数；标题、数据范围和面包屑仍需补齐下期标识。
- 总览派件司机筛选当前输入即生效，但表单仍保留查询反馈；任务、领件、退回和派件详情采用提交式筛选。后续应按第 7 章统一各页面的交互语义。
- 部分详情页重置筛选时未同时恢复默认排序；部分分页仍作为表格后的独立节点，尚未全部达到“筛选—表格—分页单一数据区域”的目标结构。
- 任务分配、派件指标、异常分布、单票工作台及司机监控内部视图切换当前没有完整 URL 深链接；刷新页面无法恢复全部上下文。
- 地图底图依赖外部瓦片服务和 WebGL；失败时可重试并继续使用列表，但当前没有离线底图降级方案。
- 运单详情和 POD 内容包含演示数据与图片；真实接口接入后仍需补充图片权限、失效链接、敏感信息审计和缓存规则。
- “妥投率”在完整司机监控与派件明细司机表中的当前分母不同，需产品确认统一口径后同步修改 Tooltip、排序字段和验收数据。
- 后续接入真实数据后，还应补充自动刷新、数据过期提示、请求重试、权限和并发更新规则。
