## 2. 需求摘要

实时看板现有应派件结果包含待派件、已签收和派送异常。实际作业中，部分待派件会在没有登记派送异常的情况下直接退回站点。为准确解释应派件结果、识别不合规退回并保持各层级数据核平，本次新增独立派件状态“非标退回”。

上线后，应派件由以下四种互斥派件状态构成：

```text
已签收、派送异常、非标退回、待派件
```

核心口径：

```text
应派件 = 已签收 + 派送异常 + 非标退回 + 待派件
日清率 =（已签收 + 派送异常）÷ 应派件 × 100%
```

非标退回不计入日清率和妥投率，不归入派送异常，也不自动进入问题件集合。

## 3. 背景与问题

### 3.1 现状

当前应派件只展示三种派件结果：待派件、已签收、派送异常。系统无法单独表达“未登记派送异常、直接退回站点”的运单。

### 3.2 用户问题

- 待派件减少后，已签收和派送异常未对应增加，用户无法解释差额。
- 直接退回与派送异常后的正常退回流程混淆，无法判断流程是否合规。
- 总览、司机、地图和运单明细缺少一致的非标退回统计与追溯路径。
- 如果把直接退回视为日清完成，会错误抬高日清率。
- “运单状态”和“派件状态”容易被混为同一维度。

### 3.3 业务价值

- 完整解释应派件结果，确保汇总可核平。
- 单独暴露不合规直接退回，便于站点和司机管理。
- 保持原有日清考核口径稳定，避免指标虚高。
- 为后续流程审计和数据治理提供独立状态与事件依据。

## 4. 目标与成功标准

### 4.1 业务目标

1. 独立统计待派件直接退回站点并完成入库的运单。
2. 在全部、当期应派、历史未派、司机和运单层级保持四状态核平。
3. 保持日清率原口径，非标退回不进入日清率分子。
4. 支持从总览查看非标退回数量，并复用应派件明细完成下钻、筛选和导出。
5. 明确区分非标退回与派送异常后的正常退回。

### 4.2 产品成功标准

- 所有应派件统计范围满足四状态之和等于应派件。
- 总览、司机监控、地图、明细和导出中的非标退回数量一致。
- 待派件转非标退回时，应派件与日清率不变。
- 四状态显示占比保留两位小数且合计严格为 `100.00%`。
- 用户可从非标退回指标进入应派件详情，页面自动应用非标退回筛选。
- “运单状态”和“派件状态”在明细表及导出中独立展示。

## 7. 术语与业务边界

| 术语 | 定义 | 维度 | 日清率分子 |
| --- | --- | --- | --- |
| 应派件 | 当前统计范围内需要产生派件结果的全部包裹 | 统计全集 | 分母 |
| 待派件 | 尚未形成有效派件结果的包裹 | 派件状态 | 不计入 |
| 已签收 | 已完成正常签收的包裹 | 派件状态 | 计入 |
| 派送异常 | 已尝试派送失败并登记派送异常的包裹 | 派件状态 | 计入 |
| 非标退回 | 未登记派送异常，直接退回站点并完成入库的应派件包裹 | 派件状态 | 不计入 |
| 待退回/已退回 | 运单进入退回流程后的处理进度 | 退回流程状态 | 取决于派件状态 |
| 运单状态 | 运单物流生命周期状态，如运输中、已妥投、已下架 | 运单维度 | 不直接参与 |
| 派件状态 | 本派件周期的结果状态，即四种互斥结果 | 派件维度 | 按具体状态判断 |

### 7.1 非标退回与正常异常退回

```text
正常异常退回：待派件 → 派送异常 → 待退回/已退回
非标直接退回：待派件 → 非标退回
```

- 正常异常退回继续统计为派送异常，不增加非标退回。
- 非标直接退回只统计为非标退回，不增加派送异常。
- 同一运单在同一派件周期、同一统计时点只能属于一种派件状态。

### 7.2 运单状态与派件状态

两者为独立字段，不得共用一个字段或只修改列名：

| 业务情况 | 运单状态示例 | 派件状态 |
| --- | --- | --- |
| 已领件、尚未完成派送 | 运输中 | 待派件 |
| 完成正常签收 | 已妥投 | 已签收 |
| 登记派送异常 | 运输中 | 派送异常 |
| 非标退回并完成入库 | 已下架 | 非标退回 |

## 8. 指标口径

### 8.1 核心等式

```text
应派件 = 已签收 + 派送异常 + 非标退回 + 待派件
```

四种派件状态必须互斥且完整。

### 8.2 日清率

```text
日清率 =（已签收 + 派送异常）÷ 应派件 × 100%
```

- 非标退回不计入分子。
- 待派件不计入分子。
- 不得再通过 `1 - 待派件率` 推导日清率。
- 待派件转为非标退回时，日清率保持不变。

### 8.3 妥投率

```text
妥投率 = 已签收 ÷ 应派件 × 100%
```

2400 妥投率继续沿用当前当期应派口径：

```text
2400 妥投率 = 当期应派中的已签收数量 ÷ 当期应派 × 100%
```

非标退回不进入分子，也不从分母剔除。

### 8.4 非标退回率

```text
非标退回率 = 非标退回 ÷ 应派件 × 100%
```

该指标只用于派件结果构成和流程异常识别。

### 8.5 百分比展示规则

所有百分比保留两位小数。对于已签收、派送异常、非标退回、待派件这组完整构成，使用“最小非零项补差”规则：

1. 依据未四舍五入的原始占比，将所有非零项从大到小排序。
2. 除最后一项外，其余项按标准四舍五入保留两位小数。
3. 最后一项，即原始占比最小的非零项，使用 `100.00% - 其余项显示占比之和`。
4. 数量为 0 的项目固定为 `0.00%`，不承担补差。
5. 计算完成后映射回固定业务展示顺序，不按占比改变界面位置。
6. 同占比时，固定业务顺序中靠后的同值项承担补差。
7. 补差只修改显示占比，不修改数量、原始比例或业务状态。
8. 分母为 0 时全部显示 `0.00%`，不执行补差。
9. 任何项目不得出现负百分比、`NaN` 或 `Infinity`。
10. 日清率、妥投率等独立指标正常四舍五入，不参与构成组补差。

固定业务展示顺序：

```text
已签收 → 派送异常 → 非标退回 → 待派件
```

## 9. 状态模型

### 9.1 派件状态枚举

| 机器值 | 展示文案 |
| --- | --- |
| `pending` | 待派件 |
| `delivered` | 已签收 |
| `exception` | 派送异常 |
| `nonstandard_return` | 非标退回 |

### 9.2 状态转换

允许的正常转换：

```text
pending → delivered
pending → exception
pending → nonstandard_return
```

状态纠错不得覆盖历史记录，必须通过更正事件记录原状态、目标状态、原因、操作人和操作时间。

### 9.3 非标退回认定条件

只有同时满足以下条件，运单才进入非标退回：

1. 运单属于当前或历史应派件。
2. 当前派件状态为待派件。
3. 没有有效派送异常记录。
4. 站点退回入库扫描成功。

仅发起退回但尚未完成站点入库时，继续保留待派件，不得提前计入非标退回。

### 9.4 幂等与冲突处理

- 同一入库扫描事件重复上报只统计一次。
- 已签收或已登记派送异常的运单，不允许通过普通扫描直接变为非标退回。
- 冲突事件进入异常处理或更正流程，不直接修改汇总差额。

### 10.3 日清率复杂 Tooltip

Tooltip 为只读结构化信息，展示内容固定为：

1. 标题“派件结果详情”。
2. 应派件数量。
3. 已签收数量及占比。
4. 派送异常数量及占比。
5. 非标退回数量及占比，并标注“不计入日清”。
6. 待派件数量及占比。
7. 日清率。
8. 公式“（已签收 + 派送异常）÷ 应派件”。

交互规则：

- 悬停任一分段均展示完整快照，不只展示当前分段。
- 命中分段可通过字重强调，但不改变字段顺序。
- Tooltip 顶部与内容顶部对齐，状态行高度自适应；非标退回的辅助说明不得造成相邻字段错位。
- Tooltip 最大宽度 `260px`，使用项目复杂 Tooltip 样式。
- Tooltip 不放置按钮、链接或下钻入口。
- 进行视口碰撞处理，不遮挡相邻 KPI。

### 10.9 应派件详情

#### 10.9.1 筛选

派件状态多选包含：

```text
已签收、派送异常、非标退回、待派件
```

#### 10.9.2 表格

- “运单编号”后依次展示“运单状态”和“派件状态”。
- 运单状态与派件状态使用独立字段，禁止将非标退回直接显示在“运单状态”列。
- 非标退回示例：运单状态“已下架”，派件状态“非标退回”。
- 其余现有字段、排序、分页和查询能力保持不变。
- 表格允许区域内横向滚动，不产生页面级横向滚动。

#### 10.9.3 导出

- 导出文件同时包含“运单状态”和“派件状态”列。
- 两列顺序与页面一致：运单状态在前，派件状态在后。
- 导出使用已提交筛选条件，不读取尚未查询的草稿条件。
- 导出数量、状态和占比必须与当前查询结果一致。

### 10.10 运单详情 Sheet

- 复用现有运单详情 Sheet。
- 不增加“退回信息”区块。
- 不单独展示退回类型、退回原因、退回站点、退回入库时间和退回操作人。
- 保留既有收件人信息、附加信息和操作记录。
- 运单状态与派件状态如同时出现，必须使用独立字段和独立标签，不得混用。

### 10.11 问题件与异常分析

- 非标退回不自动进入派送异常问题件集合。
- 非标退回不计入派送异常原因分布。
- 非标退回不自动产生 POD 不合规、妥投位置异常或虚假问题件标签。
- 已存在的派送异常后退回仍按派送异常和退回流程统计。

## 11. 页面与交互状态

### 11.1 加载状态

- 汇总、司机和明细加载使用项目 Skeleton。
- 同一批次数据未全部返回前，不拼接不同快照展示四状态结果。

### 11.2 空状态

- 非标退回数量为 0 时，总览指标、Tooltip 和筛选项仍保留。
- 下钻无结果时使用项目 Empty，文案说明当前条件下暂无非标退回运单。

### 11.3 错误状态

- 接口失败时展示可恢复错误状态，并允许重试。
- 数据无法核平时不得自动用差额修改待派件；保留上一份已核平快照或明确提示数据暂未核平。
- 时间缺失或无效时显示 `—`，不得显示无效日期。

### 11.4 刷新状态

- 总览、图表、司机列表和地图使用同一 `snapshotAt`。
- 刷新成功后所有模块同时切换到新快照。
- 刷新期间不应出现短暂的四状态不核平。

## 12. 数据需求

### 12.1 汇总数据

```ts
type DeliverySummary = {
  total: number
  pending: number
  delivered: number
  exception: number
  nonStandardReturn: number
  clearanceRate: number
}
```

服务端或共享领域层必须校验：

```text
total === pending + delivered + exception + nonStandardReturn
```

### 12.2 运单数据

```ts
type DeliveryStatus =
  | "pending"
  | "delivered"
  | "exception"
  | "nonstandard_return"

type WaybillStatus =
  | "in_transit"
  | "delivered"
  | "off_shelf"

type NonstandardReturnInfo = {
  returnedAt: string
  stationId: string
  stationName: string
  reasonCode: string
  reasonLabel: string
  operatorId: string
  operatorName: string
  scanEventId: string
}

type RecipientLocation = {
  latitude: number | null
  longitude: number | null
}
```

- 非标退回地图点只读取 `RecipientLocation`。
- `NonstandardReturnInfo` 用于认定、审计和操作记录，不在卡片或详情 Sheet 增加专属展示。
- 时间点使用含时区的 ISO 8601，页面按用户时区格式化。

### 12.3 原因字典

| 原因编码 | 建议文案 |
| --- | --- |
| `NO_EXCEPTION_RECORD` | 未登记异常直接退回 |
| `WRONG_OPERATION` | 操作流程不规范 |
| `STATION_RECALL` | 站点临时召回 |
| `OTHER` | 其他 |

前端不得使用中文文案作为业务判断条件。

## 13. 接口需求

### 13.1 总览接口

- 返回全部、当期应派、历史未派三个范围的真实四状态汇总。
- 返回 `snapshotAt`。
- 禁止使用全部应派件比例估算子范围数量。

### 13.2 司机汇总接口

- 每名司机返回应派件、四状态数量和日清率。
- 返回前执行司机级核平。
- 司机合计与站点汇总保持一致。

### 13.3 运单列表接口

派件状态查询参数支持：

```text
pending,delivered,exception,nonstandard_return
```

- 从非标退回指标进入时提交 `status=nonstandard_return`。
- 返回独立的 `waybillStatus` 和 `deliveryStatus`。
- 返回地图所需的收件人经纬度。

### 13.4 兼容策略

- 灰度期后端新增字段缺失时，前端可临时按 0 展示并记录契约告警。
- 兼容期结束后将 `nonStandardReturn` 和运单派件状态设为必填。
- 老版本客户端忽略新增字段时，既有字段语义不得变化。
- 禁止把非标退回合并到派送异常以兼容旧客户端。

## 14. 非功能需求

### 14.1 性能

- 新增状态不得显著增加实时看板首屏请求数。
- 下钻复用应派件接口，不新增重复的大列表请求链路。
- 地图点过滤和列表过滤使用同一结果集。

### 14.2 可访问性

- 非标退回必须同时使用文字、数量和颜色表达。
- 可点击指标使用按钮语义，支持 Enter 和 Space。
- 圆环支持键盘聚焦，并展示与鼠标悬停一致的 Tooltip。
- 圆环可访问名称包含应派件、四状态数量及占比、日清率和“不计入日清”说明。
- 复杂 Tooltip 中的关键信息在展开结果分布中存在等价常驻文本。
- 所有图标按钮提供中文可访问名称。

### 14.3 响应式

- 桌面端关键派件指标首屏可见。
- `390 × 844` 下页面不得产生整体横向滚动。
- 移动端结果分布采用两列网格。
- 明细表格只允许表格区域横向滚动。
- 复杂 Tooltip 宽度不超过视口减 `32px`。

### 14.4 数据一致性

- 总览、司机、地图、明细和导出共享同一状态定义。
- 百分比补差算法只能维护一份共享实现。
- 数量为真实来源，百分比不得作为独立可配置数据。

## 16. 权限与审计

- 查看权限沿用实时看板、司机监控和应派件详情现有权限。
- 本期不新增状态修改入口，因此不新增写权限。
- 非标退回认定事件必须保留扫描事件 ID、操作人、操作站点、时间和原因编码。
- 状态更正必须保留更正前后值及操作者，不得覆盖原事件。
- 导出权限沿用应派件详情现有导出权限。

## 19. 发布与回滚

### 19.1 发布顺序

1. 发布状态枚举、扫描事件认定和数据字段。
2. 发布总览、司机和运单接口，并启用核平监控。
3. 验证灰度数据，不对不可靠历史记录强制回填。
4. 发布前端展示与下钻。
5. 观察核平失败、状态写入、地图坐标和接口告警。
6. 兼容期结束后将新增字段调整为必填。

### 19.2 历史数据

- 只有能够证明“未登记派送异常且已直接完成站点入库”的历史事件才允许回填。
- 无法确认的历史运单保持原状态。
- 默认从功能上线时点开始准确统计。

### 19.3 回滚策略

- 前端通过功能开关隐藏非标退回展示时，后端事件和审计数据仍保留。
- 回滚不得把非标退回数据合并进派送异常。
- 回滚期间应派件核平失败需要明确告警，不得静默修改待派件。

## 20. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 将异常退回误识别为非标退回 | 重复统计、污染日清率 | 使用独立状态和严格认定条件 |
| 前后端公式不一致 | 页面与导出不一致 | 共享指标计算和契约测试 |
| 各组件分别舍入 | 四项占比不等于 100% | 统一最小非零项补差函数 |
| 不同模块读取不同快照 | 瞬时无法核平 | 统一 `snapshotAt` |
| 历史数据证据不足 | 制造错误记录 | 只回填证据充分事件 |
| 非标退回与派送异常颜色接近 | 用户误判 | 使用独立低饱和紫色并始终配合文字 |
| 四状态圆环被理解为均计入日清 | 错误理解指标 | 圆心明确日清率，Tooltip 展示公式和不计入说明 |
| 非标退回点被理解为包裹当前位置 | 错误判断实物位置 | 固定标注“标记位置：收件地址” |
| 运单状态和派件状态混用 | 查询及导出语义错误 | 独立字段、独立列和独立状态映射 |

## 21. 待确认事项

以下事项不阻塞 PRD 主体评审，但需在接口冻结前确认：

1. 非标退回原因字典的最终编码和中文文案。
2. 非标退回事件的权威来源及入库扫描事件类型。
3. 状态更正流程的审批人和权限范围。
4. 灰度期兼容时长及新增字段转必填时间。
5. 是否对具备完整事件链的历史数据进行有限回填。

## 22. 最终决策清单

1. 非标退回是应派件的独立、互斥派件状态。
2. 应派件由已签收、派送异常、非标退回、待派件四项构成。
3. 非标退回不计入日清率和妥投率。
4. 待派件转非标退回时日清率保持不变。
5. 派件作业摘要卡不新增非标退回 KPI。
6. 日清率圆环展示四状态，圆心仍显示日清率。
7. 复杂 Tooltip 展示完整四状态构成、日清率和公式。
8. 构成百分比保留两位小数，由最小非零项承担补差。
9. 界面固定按已签收、派送异常、非标退回、待派件展示。
10. 非标退回复用应派件详情和筛选，不新增专属详情。
11. 非标退回地图点使用收件人经纬度。
12. 运单卡片和详情 Sheet 不增加专属退回信息展示。
13. 运单状态和派件状态为独立维度，表格及导出分别展示。
