# DSP 系统权限控制设计方案

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档名称 | DSP 系统权限控制设计方案 |
| 文档状态 | 待评审 |
| 编写日期 | 2026-10-21 |
| 适用范围 | DSP 管理系统的登录准入、组织切换、菜单、按钮、接口、数据范围、隐私字段与导出 |
| 上游系统 | DMS 等维护用户、组织、角色及三者关系的身份系统；具体接口以联调契约为准 |
| 权限配置归属 | DSP 系统 |

### 1.1 已确认的业务要求

1. 按用户角色控制权限，至少覆盖菜单和按钮。
2. 登录准入按用户所属组织及该组织下的角色判断。
3. 用户、组织、角色及归属关系由其他系统维护；DSP 维护自身权限配置。
4. 部分隐私数据也要受控，司机联系电话是首批字段。

### 1.2 与既有文档的关系

《DSP基础功能PRD文档_20260622_V1》第六章写明“权限控制统一由 DMS 系统管理”，并按 DMS 返回的权限列表控制前端按钮。该口径与本次确认的职责边界冲突。本方案按最新要求设计：**DMS 提供身份、组织与角色事实，DSP 独立维护并执行本系统权限策略**。实施前应同步修订相关 PRD 和接口契约，避免两个版本同时作为验收依据。

## 2. 设计目标与边界

### 2.1 目标

- 用户在不同组织可拥有不同角色、不同系统准入和不同功能权限。
- 菜单、页面、按钮及对应接口使用一致的权限码和判定结果。
- 数据查询与操作限定在当前组织和授权业务范围内。
- 隐私字段支持脱敏查看、完整查看、完整导出等不同授权级别。
- 权限来源和拒绝原因可解释，敏感访问和策略变更可审计。
- 外部角色或组织关系变更后，已有会话中的授权能及时失效。

### 2.2 边界

| 事项 | 权威来源 | DSP 责任 |
| --- | --- | --- |
| 身份认证、账号状态 | 外部身份系统 | 接入认证结果，建立安全会话 |
| 用户、组织、角色及归属关系 | 外部身份系统 | 只读获取稳定 ID、状态和必要展示信息 |
| DSP 系统准入 | DSP | 配置组织与角色能否进入 DSP |
| DSP 功能、数据及字段权限 | DSP | 定义权限码、配置策略、服务端执行 |
| DSP 权限审计 | DSP | 记录策略变更、拒绝和敏感数据访问 |

DSP 不创建或修改上游用户、组织、角色，也不把 DMS 返回的其他系统权限直接视为 DSP 权限。个人资料或密码修改若由 DMS 负责，业务操作仍调用其接口；DSP 对入口和请求做本系统授权。

## 3. 核心概念与授权模型

| 概念 | 定义 |
| --- | --- |
| 用户 | 外部系统提供的稳定 userId |
| 组织 | 外部系统提供的稳定 orgId，DSP 数据隔离的基本边界 |
| 角色 | 外部系统提供的稳定 roleId；同名角色不以名称关联 |
| 成员关系 | 用户在某组织下拥有某角色的有效关系 |
| 当前组织 | 用户本次会话正在操作的组织，必须属于可进入组织列表 |
| 权限码 | DSP 代码登记的资源与操作标识，如 finance.bills.approve |
| 策略 | DSP 对某角色或某“组织＋角色”配置的准入、权限和数据范围 |
| 数据范围 | 权限作用的记录集合，如当前组织、所属车队或本人任务 |
| 字段策略 | 响应字段可省略、脱敏或完整返回的规则 |

一次服务端授权应满足：

~~~text
允许 = 身份有效
     且当前组织有效
     且存在该用户在当前组织下的有效角色
     且该角色的 DSP 准入已开启
     且该角色策略授予请求的操作权限
     且目标数据落在该角色对该操作的数据范围内
     且请求字段满足字段策略
~~~

**默认拒绝**：缺失成员关系、策略、权限码、目标数据范围或必要字段规则时均不放行。前端传入的 orgId、roleId、permission 列表不能作为授权事实。

### 3.1 多角色规则

同一用户在同一组织下可有多个有效角色。菜单可按这些角色的可用功能取并集；服务端对一次具体操作要求**至少有一个角色同时满足业务操作权限、目标数据范围和所需字段权限**。不得把角色 A 的“完整电话查看”权限与角色 B 的“全部司机数据范围”拼接成更大的授权。不同组织的角色和权限绝不合并。

### 3.2 通用与组织专属策略

一个外部 roleId 可以有一份 DSP 通用策略。若某组织同一角色职责不同，可建立“orgId＋roleId”专属策略。**专属策略完整替代通用策略，不自动叠加**；管理界面需提示其来源、差异和生效范围。这样可以避免“通用授予＋组织例外撤销”的隐式优先级。

第一阶段不提供用户个人授权、任意拒绝规则或复杂角色继承。确需临时授权时，优先由上游授予有有效期的角色，并在 DSP 配置该角色的权限。

## 4. 权限层级与权限码

| 层级 | 判定对象 | 例子 | 执行位置 |
| --- | --- | --- | --- |
| 系统准入 | 组织＋角色能否进入 DSP | system.access | 登录后、组织切换时及会话复核 |
| 菜单／页面 | 能否看到并进入功能 | finance.bills.read | 菜单生成、路由与接口 |
| 按钮／操作 | 能否执行动作 | finance.bills.approve | 按钮状态、业务接口 |
| 数据范围 | 能操作哪些记录 | 当前组织、所属车队、本人任务 | 服务端查询和对象校验 |
| 隐私字段 | 可见字段及可见程度 | driver.phone.full_read | 服务端响应构造 |
| 导出／下载 | 是否可批量取得数据 | driver.phone.full_export | 任务创建、文件生成、文件下载 |
| 策略管理 | 能否修改或查看权限策略 | security.policy.manage | 管理界面及管理接口 |

### 4.1 命名规范

建议采用“业务域.资源.动作”，稳定代码不随菜单中文名称改变。例如：

| 权限码示例 | 含义 |
| --- | --- |
| live_dashboard.read | 查看实时看板 |
| finance.bills.read | 查看账单 |
| finance.bills.approve | 审核账单 |
| driver.phone.masked_read | 查看脱敏司机电话 |
| driver.phone.full_read | 按次查看完整司机电话 |
| driver.phone.full_export | 导出完整司机电话 |
| security.policy.manage | 编辑 DSP 权限配置 |
| security.policy.audit_read | 查看权限审计 |

上述代码是设计示例。现有菜单中已出现 live_dashboard.read、data_cockpit.read、finance.settlement.read 等代码。实施时应整理权限目录、拆分粒度过粗的 finance.settlement.read，并建立旧码到新码的迁移映射。**权限码由版本化代码登记，后台只分配已登记权限**；未知或已停用的代码不得生效。菜单父节点仅在至少一个可访问子项存在时展示。

“有页面查看权”不自动获得按钮操作权；“有导出按钮权”不自动获得完整隐私字段导出权。权限管理界面可提示依赖关系，但服务端仍逐项校验。

### 4.2 授权项组合示例

| 角色策略 | 授权项及范围 | 结果 |
| --- | --- | --- |
| 车队主管 | driver.read：负责车队；driver.phone.masked_read：负责车队；driver.phone.full_read：负责车队 | 可查看负责车队司机的完整电话 |
| 财务查询员 | driver.read：当前组织；driver.phone.masked_read：当前组织 | 可查看当前组织司机及脱敏电话，不能查看完整电话 |
| 同一用户同时拥有以上两角色 | 各角色授权项保持原范围 | 完整电话仍仅限负责车队 |

授予 full_read 时，配置必须同时具备同一业务对象的 read 和该字段的 masked_read；授予 full_export 时，还必须具备对应业务导出权限。管理界面应在保存时校验依赖，服务端按实际请求逐项校验，不因高一级字段权限而自动推导其他操作权限。

## 5. 登录、组织切换与业务访问流程

~~~mermaid
flowchart TD
    start([访问 DSP]) --> auth[外部系统身份认证]
    auth --> authOk{认证通过}
    authOk -- 否 --> loginDenied([拒绝登录])
    authOk -- 是 --> membership[读取用户组织角色关系]
    membership --> admission[核对 DSP 组织角色准入]
    admission --> hasOrg{有可进入组织}
    hasOrg -- 否 --> entryDenied([拒绝进入 DSP])
    hasOrg -- 是 --> selectOrg[选择当前组织]
    selectOrg --> permissions[加载该组织角色策略]
    permissions --> context[生成权限上下文]
    context --> menu[按权限展示菜单按钮]
    menu --> request[请求页面或业务接口]
    menu -->|切换组织| selectOrg
    request --> valid{会话和成员关系有效}
    valid -- 否 --> denied([拒绝访问])
    valid -- 是 --> action{角色允许该操作}
    action -- 否 --> denied
    action -- 是 --> scope{目标数据在角色范围内}
    scope -- 否 --> denied
    scope -- 是 --> field{涉及隐私字段}
    field -- 否 --> normal[返回授权业务数据]
    field -- 是 --> fieldPolicy[按字段策略裁剪响应]
    fieldPolicy --> normal
~~~

### 5.1 首次登录

1. 外部系统完成账号、密码和验证码等身份认证。DSP 不依据前端页面状态判断是否登录。
2. DSP 获取用户状态和“userId、orgId、roleId、成员状态”关系，过滤停用用户、组织、角色与无效成员关系。
3. 登录角色规则按业务配置判断：取用户在**全部有效 DSP 组织**中的有效角色 ID 并集；并集为空或只有司机角色时拒绝进入，有至少一个非司机角色时通过此规则。非 DSP 组织及停用关系不参与计算；司机角色用上游稳定 ID 识别，不按展示名称比较。
4. DSP 再按每个组织自身的角色与本地 system.access 准入策略筛选可进入组织。全局登录角色规则通过，不代表可进入任意组织；没有可进入组织时仍拒绝进入 DSP。
5. 仅在可进入组织中选择当前组织；载入对应角色策略。默认组织必须经服务端确认，不能直接信任本地存储或 URL 参数。
6. 建立服务端会话。客户端仅拿到展示所需的权限摘要，不以该摘要替代服务端鉴权。

### 5.2 切换组织

切换请求必须由服务端重新核对成员关系和准入策略，再更新会话当前组织及权限版本。切换失败保留原组织。切换成功后清空原组织业务缓存、重新获取菜单和页面数据；旧组织的异步请求结果不得写入新组织页面。

### 5.3 每次业务请求

服务端从可信会话读取 userId 和当前 orgId，检查会话、当前组织准入状态及策略版本，按“操作权限＋该角色的数据范围＋字段权限”判定。这里的“每次检查”指**每个受保护的服务端请求都执行授权决策**，不要求每次重新调用 DMS，也不要求每次完整查询权限表；可使用已验证的成员关系快照和 DSP 策略缓存，并通过版本、失效通知及有效期控制其新鲜度。

纯前端菜单切换或同页标签切换可用当前组织权限摘要控制显示，无需发起一次独立的 DMS 准入查询；但只要切换触发受保护的页面请求、数据请求或操作接口，相应服务端入口就必须鉴权。直接访问 URL、手工调用 API、修改请求体中的 orgId 或资源 ID，均不能绕过校验。未认证返回 401；已认证但无权操作返回 403；不宜暴露存在性的跨组织对象可统一返回 404。具体错误码应由接口契约统一。

### 5.4 权限摘要的刷新与失效

前端权限摘要由服务端在登录、切换组织或刷新摘要时，根据当时有效的成员关系与 DSP 策略计算并下发。摘要携带当前 orgId、DSP 策略版本、外部成员关系版本或更新时间、generatedAt，用于菜单、按钮和页面提示，**不是服务端授权凭据**。因此不要求给摘要设置固定的安全有效期，也不以“摘要尚未过期”作为放行条件。

重新登录、切换组织、收到策略或成员变更通知、服务端返回权限变化或拒绝结果时，前端重新获取摘要。浏览器从后台恢复或页面停留较久时也可刷新，以减少界面与实际权限不一致的时间。如果没有可靠的变更通知，可增加定期刷新作为**界面一致性措施**，其周期不代表安全撤权时限。

每个受保护请求仍由服务端基于有效会话、当前策略版本、成员关系快照和目标数据独立授权。服务端 DSP 策略缓存与外部成员关系快照需要版本或最大有效期，防止撤权后无限期沿用旧事实；这与前端摘要是否定时刷新是两个问题。策略或成员关系变更通知应优先主动失效相关服务端缓存。

## 6. 数据范围设计

**组织隔离始终是基础条件**：业务记录必须关联归属组织，查询默认带当前 orgId，写操作还需核对目标记录 orgId。不能只在列表过滤；详情、批量操作、导出、下载和后台任务同样校验。

在组织范围内，可按业务需要配置以下数据范围：

| 范围类型 | 示例 |
| --- | --- |
| ORG | 当前组织全部记录 |
| FLEET | 用户负责的车队；车队关系来源需明确 |
| ROUTE | 用户负责的路线或路区；归属关系来源需明确 |
| ASSIGNED | 分配给当前用户的任务 |
| SELF | 用户自己的资料和文件 |

第一期只启用业务数据已能可靠提供归属关系的范围。无法确认车队、路线或任务归属时不得猜测放行。列表查询在数据源过滤；详情和操作按目标对象复核；批量请求逐条判定并返回成功与拒绝数量。

## 7. 隐私字段设计

### 7.1 字段分级

| 等级 | 例子 | 默认处理 |
| --- | --- | --- |
| 普通业务字段 | 运单状态、车队名称 | 受功能和数据范围约束 |
| 需脱敏字段 | 司机姓名、联系电话、邮箱 | 无完整查看权时按策略脱敏或省略 |
| 高敏字段 | 证件号、银行卡号等 | 默认省略；逐项设计权限与展示规则 |

字段逐一登记，不设置一个可查看所有隐私数据的笼统权限。自身个人资料的查看或修改可使用 SELF 范围和专门的个人资料权限，不应继承“查看所有司机电话”的权限。

### 7.2 司机电话规则

1. 列表、卡片与普通详情只返回接口已裁剪的脱敏电话；没有 masked_read 权限时直接省略电话字段。
2. “查看完整号码”发起独立请求。服务端依次检查当前组织、司机归属、该角色数据范围与 driver.phone.full_read，再按次返回完整号码。
3. 完整号码不得先放进列表 JSON、服务端渲染数据、HTML、浏览器存储或前端状态，再仅靠眼睛按钮遮住。前端隐藏、短时展示和复制按钮只是体验控制，不是安全边界。
4. 导出完整号码单独检查 driver.phone.full_export。没有该权限的导出应省略或脱敏电话；产品需统一选择具体格式并在导出界面标明。
5. 完整字段响应设置禁止缓存；审计记录操作人 ID、组织 ID、对象 ID、字段码、动作、结果、时间与请求关联 ID，不写入完整号码。需对连续查询和大量导出设置异常访问监测。
6. 电话搜索、复制、通知及与其他系统交互也应检查是否会暴露完整号码；如果允许按完整电话检索，不应通过搜索结果或错误提示回显完整值。

| 请求场景 | 必要授权 | 响应 |
| --- | --- | --- |
| 普通列表，无 masked_read | 业务 read | 省略电话字段 |
| 普通列表，有 masked_read | 业务 read＋masked_read，且目标在同一角色的数据范围内 | 返回脱敏电话 |
| 按次请求完整电话 | 业务 read＋full_read，且目标在同一角色的数据范围内 | 返回完整电话并记录审计；缺权返回 403 |
| 导出完整电话 | 业务 export＋full_export，且记录在同一角色的数据范围内 | 在授权导出中包含完整电话并记录审计；缺权不得包含原值 |

### 7.3 导出与下载中心

导出任务创建时校验操作与字段权限，并把组织、请求人和导出字段策略固定到任务。实际生成和文件下载时再次核对当前授权；权限被撤销后，不能依靠已生成的下载链接继续取得完整字段。文件仅在授权组织范围内可访问，下载中心不能跨组织展示任务。

## 8. 策略数据结构与外部契约

### 8.1 DSP 本地数据

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| permission_catalog | code、category、resource、action、sensitivity、status、version | 由代码发布登记，作为权限目录 |
| role_policy | policyId、roleId、orgId 可空、admissionEnabled、status、version、effectiveAt | orgId 为空为通用策略；非空为组织专属策略 |
| role_policy_grant | policyId、permissionCode、scopeType、scopeParams | 一个授权项同时携带操作权限和适用数据范围 |
| policy_change_log | actorId、policyId、before、after、reason、time | 策略变更审计 |
| sensitive_access_log | actorId、orgId、objectType、objectId、fieldCode、action、result、time | 完整字段查看与导出审计，不含字段原值 |

外部用户、组织和角色可以在 DSP 保存必要的只读快照或缓存，不能成为第二个可人工编辑的主数据。外部稳定 ID 是关联键；名称仅用于展示。

### 8.2 外部系统最低契约

| 数据 | 必要字段或能力 |
| --- | --- |
| 认证结果 | 稳定 userId、账号状态、会话有效性 |
| 组织与角色关系 | userId、orgId、roleId、成员状态、组织状态、角色状态、更新时间或版本 |
| 变更通知 | 用户停用、移出组织、角色撤销、组织停用等变更事件；至少支持定期对账 |
| 可靠性 | 查询超时、重试边界、不可用时的会话处理约定 |

DMS 现有 PRD 假设认证响应同时携带权限列表。本方案只需要身份及组织角色事实；如接口仍返回权限，DSP 不把它当作本系统授权依据。实际登录协议和同步方式需在联调前确认。

### 8.3 服务接口建议

| 接口能力 | 主要检查 |
| --- | --- |
| 获取当前会话及可进入组织 | 身份状态、成员关系、DSP 准入 |
| 切换当前组织 | 目标组织成员关系和准入 |
| 获取菜单与权限摘要 | 当前组织的有效角色策略 |
| 查询／操作业务对象 | 功能权限、组织及数据范围 |
| 按次读取完整隐私字段 | 字段权限、目标归属、访问审计 |
| 创建与下载导出文件 | 导出权限、字段权限、组织隔离和授权复核 |
| 管理权限策略 | 策略管理权限、版本冲突检查、变更审计 |

接口路径由后端实现确定；前端不应在多个页面分别复制授权算法。策略更新建议使用版本号或条件更新，避免两名管理员相互覆盖。

## 9. 权限管理后台

| 页面 | 主要能力 |
| --- | --- |
| 系统准入 | 查看外部组织和角色，为通用角色或组织专属角色开启／关闭 DSP 准入 |
| 角色权限 | 按模块配置菜单、操作、数据范围、隐私字段和导出权限 |
| 权限预览 | 输入用户与组织，展示有效角色、所用策略、最终可访问菜单和拒绝原因 |
| 变更记录 | 查看策略前后差异、操作者、原因、生效时间 |
| 敏感访问审计 | 按用户、组织、字段、对象、时间查询完整字段查看和导出事件 |

管理后台只展示上游角色和组织，不提供编辑其名称、成员或状态的入口。高敏权限，如完整隐私字段批量导出和权限策略管理，应限制授予范围；可配置“编辑—复核”双人流程，且复核人不能批准自己的变更。首次管理员通过受控初始化策略绑定外部管理员角色，避免上线后无人能管理权限。

## 10. 会话、同步与异常处理

- DSP 策略变化后递增策略版本，使相关会话下次受保护请求重新计算；高敏操作在执行前获取最新策略。策略可缓存在服务端，但须支持变更后主动失效。
- 外部成员关系变化优先通过事件通知使缓存失效，并定期对账。成员关系快照需有更新时间、版本和最大有效期；最大可接受撤权延迟由安全和业务方共同确认。授权服务可使用有效快照，不必每次调用 DMS。
- 外部认证不可用时拒绝新登录。已有会话在成员关系快照仍处于允许有效期内时可按风险等级继续处理；超过最大有效期后拒绝所有受保护业务请求，不能无限期沿用旧权限。组织切换和完整隐私字段查看等高敏请求应采用更严格的新鲜度要求。
- 上游撤销角色、停用组织或停用用户后，相关组织访问应失效。若当前组织失效，引导用户选择其他仍可进入的组织；若无可用组织则退出 DSP。
- 权限不足提示不回显隐私字段，不暴露其他组织是否存在目标记录。
- 所有权限拒绝事件记录权限码、组织、对象类型及拒绝原因代码；不记录密码、令牌或隐私字段原值。

## 11. 当前仓库现状与实施方案

### 11.1 已有基础

- src/config/navigation.ts 为不少菜单配置了 permission 属性。
- src/features/permissions/can.ts 提供对单一 permissions 数组的前端判断。
- src/features/permissions/login-access.ts 已提供纯函数：汇总有效 DSP 组织角色并判定“非唯一司机角色”，再按本地 system.access 策略筛选可进入组织；待真实 DMS 和服务端会话接入时调用。
- src/services/dsp-gateway.ts 已定义获取会话、登录和组织切换的服务接口。
- 部分司机详情已实现前端脱敏展示和查看日志的预览交互。

### 11.2 需要改造

| 当前现状 | 目标改造 |
| --- | --- |
| SessionUser 只有一个全局 role，AuthSession 只有一份全局 permissions | 改为组织内角色关系和当前组织权限上下文 |
| 登录页为预览入口 | 接入外部认证及 DSP 准入判断 |
| 组织切换主要依赖 URL 和 localStorage | 服务端校验并更新可信会话 |
| 侧边栏尚未按 permission 过滤 | 按当前组织权限生成菜单，父级随子级收起 |
| can.ts 只检查前端数组 | 建立统一服务端判定，前端仅消费授权摘要 |
| 司机完整电话已进入部分客户端数据 | 列表端服务端脱敏；完整值使用按次授权接口 |
| 查看隐私字段的日志存在前端内存 | 改为服务端持久化审计 |
| finance.settlement.read 被多个财务页面共用 | 结合实际业务拆分页面和操作权限 |

### 11.3 分阶段交付

1. **契约与目录**：确认 DMS 返回的组织内角色关系和变更机制；盘点所有页面、按钮、接口、导出和敏感字段，登记权限码。
2. **基础鉴权**：完成真实登录、准入、服务端会话、组织切换、统一授权函数和组织隔离。
3. **功能接入**：按权限过滤菜单，保护路由和业务接口；逐模块接入按钮及数据范围。
4. **隐私保护**：服务端脱敏、完整字段按次读取、导出控制、访问审计；优先覆盖司机电话。
5. **管理与运营**：上线准入配置、角色权限、权限预览、变更日志与敏感访问审计，建立外部变更对账。

上线时应先准备至少一个有效的外部管理员角色及其 DSP 初始化策略，再灰度启用默认拒绝，防止无人可登录或旧接口遗漏校验。

## 12. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 用户在组织 A 有财务角色，在组织 B 有客服角色 | 切换组织后菜单、按钮与接口权限分别变化，数据不串用 |
| 用户有菜单查看权但无审核权 | 可查看页面，审核按钮不可操作，直接调用审核接口返回拒绝 |
| 用户在同组织有两个角色：A 可看本车队完整电话，B 可看全部司机但无完整电话权 | 仅能看本车队完整电话，不得跨角色拼接扩大范围 |
| 用户直接修改请求中的 orgId 或司机 ID | 服务端以可信会话及对象归属为准，拒绝越权 |
| 用户无完整电话查看权 | 列表 JSON、HTML 和浏览器状态中均不存在完整号码；查看接口拒绝 |
| 用户有完整查看权但无完整导出权 | 可按次查看，导出文件不含完整电话 |
| 管理员撤销完整电话权限后，用户尝试再次查看或下载旧导出 | 均被重新校验并拒绝 |
| 外部系统撤销用户在当前组织的角色 | 当前组织访问失效，不能靠旧会话继续操作 |
| 未登记的新权限码出现在代码或配置中 | 默认拒绝并报告配置错误 |
| 查看完整电话成功或失败 | 留下可查询审计事件，日志不包含原始电话 |
| 用户无可进入组织 | 身份认证后显示无 DSP 权限，不能进入业务页面 |

## 13. 待联调确认事项

这些事项不改变上述权限边界，但会影响实现细节：

1. 外部认证由 DMS 直接处理还是通过统一身份服务处理；DSP 可获得哪些稳定 ID 和状态字段。
2. 外部是否支持组织内多角色、角色撤销事件及增量同步；最大允许撤权延迟。
3. 车队、路线和任务归属由哪个服务提供，哪些数据范围在首期具备可靠事实来源。
4. 完整电话在业务上允许哪些场景查看、是否允许批量导出，以及导出文件保存期限。
5. 高敏权限配置是否要求双人复核、复核角色由哪个外部角色承载。
