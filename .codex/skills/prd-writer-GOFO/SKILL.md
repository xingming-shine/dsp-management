# PRD Writer - 产品需求文档撰写技能

## 概述

本技能基于《PRD撰写标准规范V1.0》标准，指导 CodeBuddy 辅助产品经理完成标准化的 PRD 文档撰写。

**工作流程：** 前置完整性自检 → 逐模块撰写 PRD → 质量复核

**核心原则：**
- 描述"做什么"和"为什么"，不涉及"用什么技术实现"
- 前后端逻辑清晰区分但不割裂
- 引用 `references/prd-specification.md` 作为详细规范的权威依据

---

## 1. 前置完整性自检（必需步骤）

**在执行任何 PRD 撰写之前，必须先执行前置自检。** 检查用户的上下文和需求资料（包括对话历史、用户提供的文档、需求分析结果等）是否满足以下所有要求。

自检分为以下模块，逐项检查。**如果任何一项不满足，不得开始撰写 PRD，而是汇总所有缺失项后提示用户补充。**

### 1.1 文档头部信息检查

检查用户上下文是否能提取到以下信息：

| 检查项 | 要求说明 |
|:---:|:---|
| 需求名称 | 本次需求的中文名称 |
| 版本号 | 至少存在一个起始版本（如 v1.0） |
| 需求背景 | 现状和问题是否清晰描述（100-300字） |
| 目标价值 | 至少 2 条可量化或可感知的业务收益，影响的用户角色和范围 |
| 负责人/参与人 | 是否有产品负责人、评审人、参与人信息 |
| 交付物 | PRD 文档、原型、设计稿的输出情况 |

### 1.2 需求业务说明检查

| 检查项 | 前置条件 | 要求说明 |
|:---:|:---:|:---|
| 业务场景拆解 | 必填 | 覆盖正常场景+异常场景，包含所属业务环节、角色、活动/操作、要求与规则 |
| 上下游影响面评估 | 必填 | 列出所有受影响的业务环节，逐一说明是否有变更 |
| 业务流程图 | 涉及流程改动时必填 | 跨角色全景流程或核心业务流程 |
| 系统架构图 | 涉及多系统交互或新增模块时必填 | 模块划分、服务调用关系、数据流向 |
| 系统流程图 | 涉及系统流程改动时必填 | 系统间调用时序和数据流转路径 |
| 状态流转图 | 涉及单据/对象状态管理时必填 | 各状态、生命周期、限制规则 |

### 1.3 系统功能设计检查

| 检查项 | 要求说明 |
|:---:|:---|
| 功能清单 | 列出所有功能点、优先级(P0/P1/P2)、原型链接 |
| 功能详细描述 - 前端逻辑 | 每个功能模块需覆盖：<br>· 页面字段定义（字段名、是否必填、输入方式、校验规则、默认值、联动）<br>· 枚举值定义（枚举名称、值、含义、说明）<br>· 页面交互说明（操作表格：触发方式、系统响应、校验规则、成功反馈、异常处理、二次确认文案、前置条件）<br>· 通用交互模式（默认排序、分页、搜索、超长内容、多选展示）<br>· 复杂页面需补充状态与边界 |
| 功能详细描述 - 后端逻辑 | 每个功能模块需覆盖：<br>· 数据处理规则（增删改查各自逻辑）<br>· 数据来源与接口说明（来源、更新机制）<br>· 状态机与业务规则（如适用） |
| 初始化数据与配置规则 | 如功能上线依赖预置数据时必填 |

### 1.4 非功能需求检查

| 检查项 | 要求说明 |
|:---:|:---|
| 性能要求 | 接口响应时间、并发量、数据量级预期（有特殊要求时填写，无则标注"无特殊要求"） |
| 兼容性要求 | 浏览器、设备、分辨率适配 |
| 多语言要求 | 是否需要国际化支持 |
| 时区要求 | 时间存储和展示的时区规则 |
| 信息安全要求 | 数据加密、传输安全、敏感信息处理 |
| 基础设施需求 | 服务器、GPU、存储、带宽等（如适用） |

### 1.5 其他需求检查

| 检查项 | 要求说明 |
|:---:|:---|
| 风险说明 | 系统类、业务类、数据类风险点已识别 |
| 造数需求 | UAT验收的数据准备要求 |
| 埋点需求 | 页面级(PV/UV)、操作级(核心按钮点击)、行为级(关键业务节点) |
| 功能权限 | 新功能的菜单/按钮权限控制（涉及新增/修改/删除/导出功能必须按钮级控制） |
| 数据权限 | 各角色层级的数据可见范围 |
| 敏感信息处理 | 个人敏感信息脱敏、存储加密、导出限制 |

### 不满足时的处理方式

1. **汇总所有缺失项**：将以上所有检查项中不满足的部分整理成清单
2. **明确缺失内容**：指出每一项具体缺少什么信息（例如："缺少业务流程图：本次需求涉及流程改动，但未提供业务流程图"）
3. **提示补充**：用清晰的结构化格式向用户展示缺失项，要求用户补充后再调用本技能
4. **不撰写 PRD**：在用户补充完整之前，不得开始撰写 PRD 文档

> **示例提示格式：**
> ```
> ⚠️ PRD 前置自检不通过，发现以下 5 项缺失，请补充：
> 
> 1. 需求背景 — 未描述当前业务现状和问题（100-300字）
> 2. 目标价值 — 未列出可量化的业务收益（至少2条）
> 3. 业务流程图 — 本次涉及流程改动，缺少业务流程图
> 4. 【功能：XX管理】页面交互说明 — 缺少删除操作的二次确认文案
> 5. 【功能：XX管理】后端逻辑 — 缺少数据处理规则中的删除逻辑说明
> 
> 请补充以上信息后再调用 PRD 撰写功能。
> ```

## 2. PRD 文档撰写流程

当自检全部通过后，按以下顺序逐模块撰写 PRD。每个模块的详细规范参照 `references/prd-specification.md`。

### 2.1 文档头部信息

生成标准化的文档头部表格：

```markdown
| 字段 | 说明 |
|------|------|
| 需求名称 | `<从用户提供的信息提取>` |
| 版本号 | v1.0 |
| 状态 | 草稿 |
| 产品负责人 | `<提取或留空>` |
| 创建日期 | `<当前日期>` |
| 最后更新日期 | `<当前日期>` |
| 评审时间 | `<待定>` |
| 评审人 | `<待定>` |
| 参与人 | `<提取或留空>` |
```

同时生成交付物清单表格和原型要求说明。

### 2.2 需求概述

#### 1.1 需求背景

撰写 100-300 字的需求背景，包含现状描述和问题说明。

#### 1.2 目标价值 / 影响面

列出至少 2 条可量化或可感知的业务收益，说明影响的用户角色和范围。

### 2.3 需求业务说明

#### 2.1 业务场景拆解

用以下表格格式撰写：

```markdown
| 所属业务环节 | 角色 | 活动/操作 | 要求与规则（业务场景维度） |
|:---:|:---:|:---:|:---|
| `<环节名称>` | `<角色>` | `<操作描述>` | 1. 具体规则<br>2. 异常场景处理 |
```

补充上下游影响面表格。

#### 2.2 - 2.6 可选模块

根据需求性质选择性填写（业务流程图、系统架构图、系统流程图、状态流转图、技术方案概要）。

### 2.4 系统功能设计

#### 3.1 功能清单

```markdown
| 功能模块 | 功能点 | 优先级 | 原型链接 | 说明 |
|:---:|:---:|:---:|:---:|:---|
| `<模块名称>` | `<功能名称>` | P0/P1/P2 | `[链接]` | 简要描述 |
```

#### 3.2 功能详细描述

**按每个功能模块逐一撰写**，结构如下：

##### 【前端逻辑】

**A. 页面字段定义**

```markdown
| 字段中文名 | 是否必填 | 输入方式 | 格式/校验规则 | 默认值 | 联动/备注 |
|:---:|:---:|:---:|:---|:---:|:---|
| `<字段名>` | 是/否 | 文本输入/下拉选择/... | 必填；最多X字符；... | 空/请选择/... | 联动说明或特殊交互 |
```

**B. 枚举值定义**

```markdown
| 枚举名称 | 值 | 含义 | 说明 |
|:---:|:---:|:---|:---|
| `<枚举类别>` | `<值>` | `<含义>` | 默认值/触发条件/关联影响等 |
```

**C. 页面交互说明**

```markdown
| 操作 | 触发方式 | 系统响应 | 表单校验规则 | 成功反馈 | 失败/异常处理 | 二次确认文案 | 前置条件/互斥规则 |
|:---:|:---|:---|:---|:---|:---|:---|:---|
| 新增 | ... | ... | ... | ... | ... | —— | —— |
| 删除 | ... | ... | ... | ... | ... | "确认文案" | 前置条件 |
```

通用交互模式表格：

```markdown
| 交互要素 | 说明/规则 |
|:---:|:---|
| 默认排序规则 | 如：按更新时间倒序 |
| 分页逻辑 | 每页默认条数、分页交互方式 |
| 搜索方式 | 支持模糊/精确搜索、组合筛选、重置操作 |
| 超长内容处理 | 文本截断 + 悬浮展示完整内容 |
| 多选字段展示 | 默认展示N个，超出用"..."代替，悬浮展示全部 |
```

**D. 状态与边界（如适用）**

```markdown
| 页面状态 | 触发条件 | 页面表现 | 用户可做什么 |
|:---:|:---|:---|:---|
| 加载中 | ... | ... | ... |
| 正常 | ... | ... | ... |
| ... | ... | ... | ... |
```

##### 【后端逻辑】

**E. 数据处理规则**

按操作说明后端逻辑（新增/编辑/删除/查询各自的数据写入、变更、校验规则）。

**F. 数据来源与接口说明**

```markdown
| 数据/字段 | 来源说明 | 更新机制 |
|:---:|:---|:---|
| `<字段/数据>` | 从XX系统/XX表获取/用户输入/系统自动生成 | 实时/定时任务/触发更新 |
```

**G. 状态机与业务规则（如适用）**

说明各状态转换条件、不同状态下允许/禁止的操作、状态变更触发方式。

#### 3.3 初始化数据与配置规则（如适用）

```markdown
| 数据类别 | 数据内容 | 数据量 | 初始化规则 | 后续维护方式 |
|:---:|:---|:---:|:---|:---|
| `<类别>` | 具体数据项描述 | X条 | 一次性导入/系统生成/手工配置 | 页面维护/定时更新/配置文件 |
```

### 2.5 非功能需求

用表格填写各维度要求。无特殊要求标注"无特殊要求，遵循系统统一标准"。

### 2.6 其他需求

填写风险说明、造数需求、埋点需求。

### 2.7 权限及安全要求
- [ ] 功能权限到每个按钮级
- [ ] 数据权限到每种角色层级
- [ ] 敏感信息处理方式已说明
填写功能权限表格、数据权限表格、敏感信息处理说明。
注：此版块严格按照公司安全信息标准，详细规范请参考 `references/prd-specification.md` 中 6.3 敏感信息处理模块。

## 3. 质量自检清单

PRD 撰写完成后，逐项复核以下清单，确保无遗漏：

### 3.1 需求概述
- [ ] 需求背景描述清晰（现状+问题）
- [ ] 目标价值 ≥ 2 条可量化/可感知收益
- [ ] 影响的用户角色和范围已明确

### 3.2 需求业务说明
- [ ] 业务场景拆解完整（覆盖正常+异常场景）
- [ ] 上下游影响面已评估
- [ ] 涉及流程改动的已提供业务流程图
- [ ] 涉及多系统交互的已提供系统架构图
- [ ] 涉及系统流程改动的已提供系统流程图
- [ ] 涉及状态管理的已提供状态流转图
- [ ] 技术驱动型需求已补充技术方案概要

### 3.3 系统功能设计
- [ ] 功能清单已列出所有功能点、优先级和原型链接
- [ ] 每个功能的【前端逻辑】已覆盖：
  - [ ] 页面字段定义（含格式/校验规则、联动逻辑）
  - [ ] 枚举值以表格完整列出
  - [ ] 交互说明表格覆盖增删改查等核心操作
  - [ ] 列表页的通用交互模式已说明（排序、分页、搜索、超长处理）
  - [ ] 涉及删除/停用等操作有二次确认文案
  - [ ] 复杂页面的状态与边界已补充
- [ ] 每个功能的【后端逻辑】已覆盖：
  - [ ] 数据处理规则（增删改查各自的后端逻辑）
  - [ ] 数据来源和更新机制已说明
  - [ ] 后端校验规则已明确
  - [ ] 涉及定时任务/外部系统调用已说明规则
  - [ ] 涉及状态流转的已说明状态机规则
- [ ] 涉及初始化数据/配置规则的已独立列出

### 3.4 非功能需求
- [ ] 有特殊要求的维度已明确标注
- [ ] 需分阶段验证的已提供数据验证与上线计划

### 3.5 其他需求
- [ ] 风险点已识别并说明
- [ ] UAT造数需求已明确
- [ ] 埋点需求已覆盖（页面级+操作级+行为级）
