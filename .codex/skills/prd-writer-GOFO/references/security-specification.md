# 20260618GUS系统安全规范 V1.0

# GUS系统安全规范

# **目的**

为明确GUS安全开发管理的强制性底线要求，确立不可逾越的安全红线，确保软件产品安全性，保障用户数据安全，特制定本规范。

# **适用范围**

本规范适用于集团内部自主开发、外包开发、合作开发的所有软件系统，包括但不限于：Web应用系统、移动应用（Android/iOS）、小程序/H5应用、API接口服务

# **适用对象**

本规范适用于以下全体人员：技术负责人、项目负责人、产品经理、需求分析人员开发工程师、测试工程师、

外包开发人员、合作方开发人员

# **规范要求**

## 敏感信息处理

### **数据采集：**

- 遵循“先告知后同意”原则，用户同意前不得收集任何信息；

- 严禁收集非业务必需的敏感数据；

### **数据使用展示\导出：**

- 功能列表如无必要不要批量显示敏感信息字段，如果必须需可以点击单行的小眼睛展示单条敏感信息，默认展示的时候是脱敏状态。公司类的数据不做强要求。

- 个人敏感信息统一不允许导出；如果需要可以通过工单实现。

- 如果需要查看个人敏感信息，可以通过查看单条数据的详情界面进行单个信息查看；

### **数据存储：**

- 用户密码必须采用不可逆的算法存储；

- 个人信息在数据库中必须加密存储（如AES\-256），严禁明文落库；加密密钥须通过密钥管理服务（apollo）管理，与数据库分开存放。

- 特别声明：在美国经纬度精确到小数位超过2位\(千米差异\)的敏感信息属于最高优先级。存储必须加密存储，不允许跨境使用\(超美国范围\),不允许回传给客户或者第三方供应商\.如特殊场景需要需要单独评估。

### **数据传输\跨境：**

- 严禁向受关注国家 / 实体传输、共享、出售批量敏感数据

- 公网开放的所有系统启用HTTPS\+TLS1\.2以上版本

### **日志记录：**

- 系统增、删、改、导出、敏感信息查询必须记录操作日志

- 日志内容包括：操作人 、操作时间 、操作IP、操作对象、操作类型、操作结果；

- 日志中禁止明文敏感信息

- 日志保存时间不少于12个月。

### **数据删除：**

- 按照业务需求符合最小必要原则即可，对于受监管交易相关的记录（内部的交易类型判定以及详情的文件，比如14117项目的一些报告和过程记录文件）至少保存10年

## 权限与访问控制

- 强制登录：涉及业务数据的页面和接口必须校验登录状态。

- 垂直越权：普通用户不得执行管理员操作；

- 禁止仅依赖前端菜单隐藏来保护敏感功能。

- 水平越权：数据操作须校验当前用户对目标数据的归属权，禁止仅凭资源ID执行数据操作，确保无越权行为。

- 未授权访问：生产系统所有操作必须进行权限校验，禁止未授权访问

## 业务逻辑与风控

- 防刷与频次限制

- 发送短信/邮件必须做到频次限制，避免轰炸和资金损失；

- 登录接口必须有防暴力破解机制，如登录失败5次锁定账号10分钟；

- 关键业务接口须配置二次验证的保护机制。

## 输入与输出安全

- SQL注入：所有数据库交互操作必须使用参数化查询，禁止通过字符串拼接方式构造SQL语句；

- XSS攻击：对用户输入进行有效性过滤，输出时进行编码转义，禁止直接输出未经处理的用户输入内容。

- 文件上传安全：类型限制：限制上传文件类型，禁止只校验后缀，必须读取文件头（Magic Number）校验真实类型，限制上传文件大小，仅允许白名单后缀；

- 文件存储安全：上传的文件禁止存放在Web根目录，需要存储在S3存储桶中，并对存储桶进行权限隔离。

- 文件导出安全：必须走异步任务，通过下载中心下载；

- 数量与频次管控：限制导出数据条数与时间范围，禁止在单位时间内无限次导出数据；
